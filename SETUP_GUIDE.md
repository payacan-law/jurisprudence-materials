# Jurisprudence | Юриспруденция — инструкция по запуску

Сайт полностью готов: дизайн переделан под ваш логотип и палитру, добавлены
вход по логину/паролю, раздел «Тесты» с сохранением результатов, «Профиль»
с прогрессом и полноценная админ-панель (добавление/удаление пользователей,
добавление/удаление категорий и вопросов тестов).

Всё это работает **бесплатно**, на бесплатном тарифе Google Firebase
(Firestore) — его щедрого бесплатного лимита с запасом хватит на 20 человек.

Единственное, что нужно сделать перед запуском — один раз завести бесплатный
проект Firebase и вставить его данные в файл `firebase-config.js`. Это займёт
5–10 минут.

---

## Шаг 1. Создать проект Firebase

1. Откройте https://console.firebase.google.com и войдите с любым Google-аккаунтом.
2. Нажмите **Add project** («Добавить проект»).
3. Введите любое название, например `jurisprudence-app`.
4. На шаге про Google Analytics — выключите (не обязательно). Нажмите **Create project**.

## Шаг 2. Включить базу данных Firestore

1. В меню слева: **Build → Firestore Database**.
2. **Create database**.
3. Выберите ближайший регион (например `eur3` или любой доступный) → **Next**.
4. Выберите **Start in test mode** → **Create**.
   (Это временный режим — ниже мы поставим правила понадёжнее.)

## Шаг 3. Включить анонимную авторизацию

Она нужна только для того, чтобы случайные посетители из интернета не могли
напрямую читать вашу базу данных, минуя сайт.

1. **Build → Authentication → Get started**.
2. Вкладка **Sign-in method** → **Anonymous** → включить (**Enable**) → **Save**.

## Шаг 4. Настроить правила доступа Firestore

1. **Build → Firestore Database → Rules**.
2. Замените содержимое на:

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /{document=**} {
      allow read, write: if request.auth != null;
    }
  }
}
```

3. **Publish**.

Это значит: читать и писать в базу может только тот, кто зашёл на ваш сайт
(сайт сам незаметно авторизуется анонимно). Это базовый, но разумный уровень
защиты для приватного инструмента на 20 человек — не путайте с банковской
защитой, см. раздел «О безопасности» ниже.

## Шаг 5. Скопировать конфигурацию в проект

1. Нажмите на шестерёнку рядом с **Project Overview** → **Project settings**.
2. Прокрутите до **Your apps** → нажмите значок **`</>`** (Web).
3. Введите любое имя приложения → **Register app** (хостинг Firebase Hosting не подключаем, просто закрыть мастер).
4. Скопируйте объект `firebaseConfig` — он выглядит так:

```js
const firebaseConfig = {
  apiKey: "AIzaSy...",
  authDomain: "jurisprudence-app.firebaseapp.com",
  projectId: "jurisprudence-app",
  storageBucket: "jurisprudence-app.appspot.com",
  messagingSenderId: "123456789",
  appId: "1:123456789:web:abcdef123456"
};
```

5. Откройте файл **`firebase-config.js`** из архива, который я подготовил, и
   замените в нём заглушку `firebaseConfig` на скопированный объект. Сохраните файл.

Готово — конфигурация закончена, дальше сайт всё делает сам.

## Шаг 6. Разместить сайт бесплатно в интернете

Проще всего — **GitHub Pages** (полностью бесплатно, свой адрес вида
`имя.github.io/jurisprudence`):

1. Создайте аккаунт на https://github.com (если его ещё нет).
2. Создайте новый репозиторий, например `jurisprudence-site` (можно приватный или публичный — на доступ к сайту это не влияет).
3. Загрузите туда все файлы: `index.html`, `app.js`, `firebase-config.js`,
   `book_data.js`, `npa_data.js`, `logo.png` (через кнопку **Add file → Upload files** на сайте GitHub — программировать не нужно).
4. **Settings → Pages → Source: Deploy from a branch → main / (root)** → **Save**.
5. Через минуту-две сайт появится по адресу вида
   `https://ваш-логин.github.io/jurisprudence-site/`.

Альтернатива (тоже бесплатно, иногда даже проще): перетащить папку с файлами
на https://app.netlify.com/drop — получите ссылку сразу.

## Шаг 7. Первый запуск — создание администратора

1. Откройте сайт по полученной ссылке.
2. Так как пользователей ещё нет, появится экран **«Первый запуск»**.
3. Введите своё имя, придумайте логин (например `admin`) и пароль → **Создать аккаунт администратора**.
4. Вы автоматически войдёте под этим аккаунтом — это ваш главный, административный доступ.

## Шаг 8. Добавить остальных 19 человек

1. В приложении: **Профиль → Панель администратора → Пользователи**.
2. Кнопка **+** внизу справа → указать имя, логин, пароль, роль (обычно «Пользователь») → **Добавить**.
3. Логин и пароль сообщите человеку любым удобным способом (лично, в мессенджере).
4. Чтобы забрать доступ — там же, в списке пользователей, нажмите значок корзины напротив нужного человека.

## Шаг 9. Наполнить раздел «Тесты»

1. **Профиль → Панель администратора → Тесты**.
2. Кнопка **+** — создать категорию (например «Уголовное право»).
3. Зайдите в категорию → кнопка **+** — добавить вопрос: текст вопроса, 4 варианта
   ответа, отметить правильный.
4. Если хотите быстро увидеть, как это работает — на пустом экране «Тесты» есть
   кнопка **«Загрузить примеры вопросов»**, она создаст 3 тестовые категории с
   вопросами, которые потом можно отредактировать или удалить.

Раздел «Теория» (термины, даты, цитаты) и «Нормативные акты» уже полностью
заполнены из ваших файлов `book_data.js` и `npa_data.js` — их редактировать
через админ-панель не нужно; я оставил их в текущем виде, так как они уже
готовы. Если в будущем понадобится отредактировать или расширить именно эти
разделы — дайте знать, это можно добавить в админ-панель отдельным этапом.

## Что делает каждый файл

| Файл | Назначение |
|---|---|
| `index.html` | разметка и стили страницы |
| `app.js` | вся логика приложения (экраны, вход, тесты, админка) |
| `firebase-config.js` | **единственный файл, который нужно заполнить** — ключи вашего Firebase-проекта |
| `book_data.js` | данные раздела «Теория» (термины/даты/цитаты) |
| `npa_data.js` | данные раздела «Нормативные акты» |
| `logo.png` | ваш логотип |

## О безопасности (важно прочитать)

Это приватный инструмент для узкого круга людей, а не публичный сервис — и
сделан соответствующим образом, просто и без лишних затрат:

- Пароли хранятся не в открытом виде, а в виде SHA-256 хэша — сам пароль в
  базе не виден.
- Доступ к базе Firestore закрыт правилом «только авторизованный на сайте»,
  как настроено в Шаге 4.
- При этом это **не банковский уровень защиты**: у любого, кто открывал бы
  исходный код страницы, есть технический доступ к тем же Firestore-вызовам,
  что делает и сам сайт. Для 20 доверенных людей, где на кону не деньги и не
  личные документы, а учебные материалы, это разумный компромисс между
  простотой, бесплатностью и защитой.
- Не используйте для этих аккаунтов пароли, которые вы используете где-то ещё.
- Если в будущем понадобится более серьёзный уровень защиты (например, сайт
  вырастет за пределы close-круга), можно перейти на полноценную Firebase
  Authentication с индивидуальными e-mail-аккаунтами — тогда потребуется
  доработка (дайте знать, когда будет актуально).

## Что можно доработать позже

Вы сами упомянули, что это будет меняться — вот что имеет смысл добавить
следующими шагами, когда решите, что нужно:
- редактирование текстов «Теории» и «Нормативных актов» прямо из админ-панели
  (сейчас это статичные файлы, отредактированные вручную через Claude);
- смена пароля пользователем самостоятельно;
- экспорт результатов тестов в таблицу;
- push-уведомления / напоминания заниматься.

Просто напишите, что из этого нужно — доделаем.
